# Politique de sécurité

## Signaler une vulnérabilité

**N'ouvrez pas d'issue publique.** Écrivez en privé à **menuwebservice@gmail.com**, en indiquant :

- la version ou le commit concerné ;
- une description du problème et de son impact ;
- les étapes pour le reproduire, si possible.

N'incluez aucun secret réel, aucun jeton et aucune donnée personnelle. Lorsque le dépôt sera public, le signalement privé de GitHub (*Private vulnerability reporting*) sera aussi activé.

## Engagements

- Accusé de réception dans un délai raisonnable, puis échange privé jusqu'à la correction.
- Divulgation coordonnée après la mise à disposition d'un correctif.
- Un secret publié par erreur est **révoqué** immédiatement : réécrire l'historique ne remplace jamais la révocation.

## Périmètre

Les exigences de sécurité du projet sont décrites dans la documentation ORI (décisions D60–D66 et D112). Une revue de code ne prouve pas qu'un composant est sûr ; chaque contrôle important doit avoir un test qui échoue si le contrôle est retiré.
